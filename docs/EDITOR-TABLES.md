# 编辑器基础表格专项

## 使用方式与范围

编辑器上方新增「表格」菜单，原有正文工具、保存入口、审稿流程和权限规则继续沿用。可插入含表头的 3 × 3 表格或普通 2 × 2 表格，再按光标所在位置增删行列、切换当前行表头或删除整张表格。存在正文选区时，菜单插表在选区末尾插入，不删除所选原文。删除最后一行或最后一列也会删除表格，误操作可用原有撤销功能恢复。

单元格支持文字、空值、段落、换行和现有基础文字格式。Tab / Shift+Tab 在单元格间移动，末尾 Tab 可增行，达到上限时停止增加。宽表在正文内部横向滚动，只读版本保留相同表格结构。

限制集中在 `lib/novel-table.ts`：每张表格最多 100 行、30 列，且总单元格不超过 2000；带表格的单次剪贴板输入最多 100 万字符。上限同时约束交互事务和服务端保存。

不支持合并单元格、嵌套表格、公式计算、宏、图表、筛选器、复杂条件格式、精确跨页布局或高保真 Office 排版。

## 从 Excel、WPS 和 Word 粘贴

1. 在源应用选择连续的矩形区域并复制，在编辑器使用普通粘贴。
2. 带 HTML 表格的剪贴板保留行列、空单元格及 `th` 表头。Office 的字体、边框和条件格式采用编辑器基础样式，公式只取复制时的显示文字，不读取或执行公式元数据。
3. 只有纯文本时识别规则的 TSV 数据，支持双引号转义、CRLF 和引号包裹的单元格内换行；至少两列才会按 TSV 表格识别。没有 HTML 的单列文本继续按普通正文粘贴。
4. 在已有表格中粘贴矩形数据，会从当前单元格或所选区域覆盖对应单元格，必要时扩展行列；可撤销恢复。源数据覆盖区域的单元格类型以源数据为准，可再用「切换当前行表头」设置表头。
5. 合并、嵌套、不规则或行列超限的 HTML 表格降级为文本并提示；不规则或超限 TSV 沿用纯文本粘贴。超过字符总量的输入直接取消，保留原选区，请分批复制。
6. 明确使用「粘贴为纯文本」时不自动创建表格。编辑器内部复制表格保留已有基础格式，仍由 Tiptap schema 解析。

桌面 Office/WPS 的剪贴板存在平台与版本差异，本次不承诺历史版本和私有非标准格式完全兼容。自动测试中的 Excel/WPS/Word 数据为合成结构夹具，不代表已逐一操作所有源应用验收。

## 保存、版本、清稿和导出

表格仍存储在 Novel Editor JSON v1 中，无数据库迁移、无全文格式转换。新增节点为 `table → tableRow → tableCell/tableHeader → paragraph`，合并属性固定为 `colspan=1`、`rowspan=1`。表格仅位于文档顶层，从列表或引用粘贴时由文档模型提升到正文层，避免隐藏在其它块内而丢失导出结构。服务端在写草稿前校验表格，并从 JSON 重算投影，非法表格返回 HTTP 400 / `DOC_TABLE_INVALID`。

现有 `onUpdate`、中文输入法收口门禁、自动保存队列及乐观锁继续工作。提交版本、交接草稿、取消定稿后恢复的草稿均复制完整 JSON。历史只读编辑器使用相同的扩展集。没有新增任意历史版本回滚入口，沿用项目已有恢复流程。

纯文本投影以制表符分列、换行分行；JSON 才是结构真相源，含单元格内换行的投影不作为可逆表格交换格式。清稿递归清除协作标记和删除态文字，保留表格、空行和空单元格；质检合稿、重新质检复用同一清稿结构提取。清稿阅读页仅在含表格时启用结构展示，历史普通正文仍沿用原有展示。

Word 导出使用真正的 Word Table / TableRow / TableCell，保留基础行列、空单元格、表头底色、段落及已有基础文字格式；不会生成公式域或合并单元格。原有文本兜底和导出路由继续使用。

## 批注、修订和输入法兼容边界

普通正文的批注、修订、中文输入和自动保存实现保持原有路径。单个单元格的文字输入及普通文字粘贴沿用文字修订逻辑。在修订模式下用表格替换表格外的正文选区时，原文和批注锚点继续保留为修订原文，新增表格文字作为插入文字处理；空表格替换也保护原文。表格内部的二维覆盖由官方表格插件处理，不生成可接受/拒绝的表格结构修订。表格操作会正常保存，也可以撤销重做。

多单元格选区不使用原有线性文字修订替换，也不展示文字浮动工具栏。表格内的完整批注审计、跨单元格修订和结构修订不属于本专项承诺；删除行列、覆盖粘贴会移除被替换单元格的原内容和标记。输入法仍在组合时，表格菜单提示先完成输入。

## 标准验收矩阵

自动测试夹具位于 `tests/support/table-fixtures.ts`，可以扩充真实源应用导出的 HTML 样本。

| 样例 | 操作与预期 |
| --- | --- |
| 2 × 2 普通表格、3 × 3 表头表格 | 插入、增删行列、切换表头、删除；撤销重做恢复结构 |
| 名称 / 数量 / 备注三列，包含中文、数字、空值 | Excel、WPS、Word 连续复制后行列一致，前后正文仍保留 |
| 公式 `=SUM(...)`，显示值为 3 | 只出现文字 3，没有公式属性或计算功能 |
| 含 CRLF、双引号、单元格内换行的 TSV | 换行与空列不丢失；强制纯文本粘贴不转为表格 |
| 已有 2 × 3 表格内覆盖左侧 2 × 2 区域 | 仅覆盖对应四格，右侧两格保留；一笔撤销恢复 |
| 合并、嵌套、不规则 HTML、超限行列 | 文本降级与提示，正文内容仍可阅读 |
| 超过 100 万字符且原先选中了正文 | 取消粘贴，原选区内容保持不变 |
| 100 × 20 表格和 5000 段正文 | 验证结构、计数；继续输入不产生超限表格 |
| 保存、提交版本、取消定稿恢复、只读 | JSON 中行列、表头、空单元格和文字完整 |
| 清稿、重新质检、Word 导出 | 删除态文字不进入交付稿；表格结构保留，Word 中为真实行列 |
| 普通正文批注修订、单元格中文组合输入 | 原有回归测试通过，组合输入最终文字和结构正确 |

本次已通过浏览器页面操作验证菜单插入、二维粘贴、菜单增行、清稿和只读展示；自动化验证另覆盖保存服务、版本快照与恢复、质检合稿、Word XML 和输入法事务。真实 Office/WPS 应用版本、真实数据库全流程、操作系统原生输入法候选窗仍按部署环境人工验收，不以 DOM 模拟测试代替。

## 本地运行与回归

```bash
npm ci
npx prisma generate
npm test
npm run typecheck
npm run lint
npm run dev
```

`prisma generate` 只生成本地类型与客户端，不迁移数据库。默认开发地址为 `http://localhost:3000`；需要指定端口时使用项目原有 Next.js 参数即可。本次按用户要求直接启动开发服务，不变更 `run.sh`、Nginx 或数据库配置。

## 发布与回滚

正式发布仍沿用项目既有发布流程，先备份应用版本和数据库，再在测试环境执行上述验收矩阵。表格能力涉及编辑器和后端，应整体发布，避免新前端连接缺少表格处理的旧后端。

需要回滚时，优先回退到仍包含表格节点、读取及导出能力的修复版本。不能直接让缺少表格扩展的旧编辑器读取并保存已经含表格的稿件，否则可能丢失结构。必须退回不支持表格的版本时，先停止相关稿件编辑并保留原始 JSON 备份；确认恢复方案后再开放编辑，不自动把已落库的表格转成文本。本次无需数据库反向迁移。
