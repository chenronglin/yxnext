# 《阅享小说智能创作系统委托开发合作合同》技术升级合同协议

## （悦享小说创作平台基础改造项目）

甲方（委托方）：深圳市阅享科技文化有限公司  
乙方（开发方）：南京安裕达信息科技有限公司

甲乙双方就此前签署的《阅享小说智能创作系统委托开发合作合同》（下称“原合同”）履行过程中的系统技术升级事宜，本着平等、自愿、诚实信用原则，经友好协商，订立本协议。本协议为原合同不可分割的组成部分，与原合同具有同等法律效力。

## 一、项目内容与合同范围

1. 本次项目名称为“悦享小说创作平台基础改造项目”，属于在现有小说创作平台上的增量改造，不属于重新开发全新系统。
2. 本次改造仅包括本协议附件一第 2.1 条列明的 SI 信息扩展、正文第 0 章、批注回复、工作日计划，以及上述功能必需的数据库变更、权限校验、回归测试、部署和使用说明。
3. 本次改造的业务规则、工作量、交付物、验收标准和范围边界，以附件一《悦享小说创作平台 20 个工作日基础改造技术附件》（下称“技术附件”）为准。
4. 技术附件是本协议不可分割的组成部分，与本协议正文具有同等法律效力。技术附件未列明或明确排除的功能，不属于本次固定价款的交付和验收范围。
5. 本次改造属于原合同约定的经双方书面确认的需求变更，除本协议另有约定外，双方相关权利义务继续按照原合同执行。

## 二、开发周期

1. 自本协议签字生效之日起，项目开发周期为 **20 个工作日**。乙方应在该周期内完成需求确认、设计、开发、内部测试、部署及使用说明，并具备交付验收条件。
2. 甲方应在项目启动时提供现有平台最新代码、数据库结构、测试与生产环境权限、脱敏测试数据、业务规则确认及部署所需资料。
3. 因甲方未按时提供资料、环境、账号、确认意见或验收反馈，或现有系统存在未提前披露的重大差异，导致乙方无法正常推进的，开发周期按实际受影响时间相应顺延。
4. 技术附件中的 **20 人日**为本期工作量控制值。新增需求或既有规则发生重大调整时，双方应另行书面确认费用和工期。

1. 本次技术升级合同总金额为：**人民币 5,000 元（大写：人民币伍仟元整）**，价款不含税费，无其他隐藏开发成本。
2. 付款方式：本协议签订生效当日，甲方一次性全额支付全部技术升级费用至原合同约定的乙方收款账户：

   开户行：中国银行南京太平南路支行  
   户名：南京安裕达信息科技有限公司  
   账号：472866351453

3. 上述合同金额包含技术附件约定的设计、开发、测试、部署支持和使用说明工作，不包含服务器、域名、SSL 证书及其他第三方资源的采购、订阅或服务费用。
4. 因甲方新增需求、调整已确认规则或要求实施技术附件明确排除事项而产生的费用，不包含在本合同金额内，按照本协议第六条执行。

## 四、ChatGPT Pro 账号交付约定

甲方应在本协议签署当日向乙方提供可正常使用的 ChatGPT Pro 账号，专供乙方完成本次基础改造的 AI 辅助开发和调试使用；该账号会员服务费由甲方全额承担。项目竣工后，双方另行协商账号返还事宜。

## 五、双方配合义务

1. 甲方应指定唯一需求对接人和业务验收负责人，负责规则确认、测试组织及验收意见汇总。
2. 甲方应保证其提供的代码、数据、账号、凭证和技术资料来源合法，并有权授权乙方在本项目范围内使用。
3. 甲方应按时提供 SI 类型、创作难度选项及必填规则，工作日日历和日期计算口径，以及可用于验证第 0 章、批注回复和工作日计划的脱敏数据。
4. 乙方应按照本协议及技术附件完成技术设计、开发、自测、回归测试、部署和使用说明，并对 AI 辅助生成的代码进行人工审查、调试和验证。
5. 乙方应妥善保管甲方提供的账号、凭证和业务资料，仅限本项目使用；项目结束后的返还、删除或继续保管按照原合同及甲方书面要求执行。

## 六、需求确认与变更管理

1. 技术附件第 2.1 条所列范围在本协议签署后视为本期开发基线，双方应在相关开发开始前完成业务规则的书面确认。
2. 任何新增、删除或修改功能、业务规则、数据范围、交付物或验收口径的要求，均须由双方书面确认后生效。未确认的口头讨论或建议不直接构成范围变更。
3. 乙方收到变更请求后，有权评估其对技术方案、20 人日控制值、合同金额、开发周期和既有成果的影响。双方完成书面确认后，乙方再实施变更。
4. 未经书面确认的范围外工作，乙方有权不予实施，且不构成延期、缺陷或违约。

## 七、交付与验收

1. 乙方完成开发及内部测试后，应向甲方书面发起验收申请，并交付技术附件第 4 条列明的功能、数据库变更、测试结果、部署版本和使用说明。
2. 本项目验收规则及缺陷分级继续沿用原合同和原附件《阅享小说智能创作系统需求规格说明书》约定的 P0/P1/P2 判定标准；技术附件第 3 条功能规则和第 5 条验收标准作为本次改造的专项验收依据。
3. 甲方应按照原合同约定的时限组织验收并一次性汇总书面意见。乙方对属于本协议范围且可复现的缺陷负责修复；新增需求、规则变化、使用方式变化或范围外事项不作为缺陷处理。
4. 存量项目无需补填新增 SI 字段，也不强制自动创建第 0 章。该等向后兼容规则不作为未完成或验收不合格处理。

## 八、知识产权、保密与维保

1. 本项目源代码、交付成果、既有系统、第三方开源软件及相关知识产权的归属和使用范围，继续按照原合同约定执行。
2. 双方对履约过程中知悉的源代码、账号凭证、业务数据、技术资料和商业信息承担的保密义务，继续按照原合同约定执行。
3. 本次改造功能的缺陷修复、免费维护期限、支持范围及维护期满后的服务安排，继续按照原合同约定执行；本协议另有明确约定的除外。

## 九、违约责任

1. 双方违约责任继续按照原合同约定执行。本协议约定与原合同不一致的，以本协议为准。
2. 因甲方未履行付款、资料提供、环境准备、业务确认或验收配合义务导致的延期或损失，由甲方承担相应责任，乙方工期相应顺延。
3. 技术附件明确不包含的功能、资源、服务和费用，不构成乙方的合同义务。

## 十、其他约定

1. 除本协议另行约定的事项外，原合同其余所有条款，包括付款、维保、知识产权、保密、违约责任、争议解决等，维持不变并继续约束甲乙双方。
2. 本协议正文、技术附件与原合同内容存在冲突的，依次以本协议正文、技术附件、原合同的顺序适用。
3. 本协议一式两份，甲乙双方各留存一份，自甲乙双方签字之日起生效，其中甲方应加盖公章，乙方签字。
4. 本协议未尽事宜，由双方另行协商并以书面补充协议确认。

## 1. 实施原则

- 继续沿用现有系统架构、账号角色、项目权限、稿件流程、版本机制、质检与导出能力，不进行整体重构。

- 新增数据结构保持向后兼容，存量 SI 和存量项目不强制补录或迁移。
- 本期严格按照 20 人日控制范围实施；范围外需求须另行书面确认。

## 2. 20 个工作日基础改造

### 2.1 范围

- SI 信息扩展；
- 正文第 0 章；
- 批注回复；
- 工作日计划；
- 上述功能所需的数据库变更、权限校验、回归测试、部署及使用说明。

### 2.2 工作量

| 工作项 | 工作内容 | 20 日控制值 |
| --- | --- | ---: |
| 需求确认、基线核对与技术设计 | 冻结业务规则，核对现有代码和数据库，设计 Migration、回滚方案及测试清单 | 1.5 人日 |
| SI 信息扩展 | 新增字段、字典或配置、表单、详情、快照、版本、回滚和存量兼容 | 2.5 人日 |
| 正文第 0 章 | 唯一性、创建、排序、提交退回、质检、定稿、接口、清稿和导出适配 | 3.5 人日 |

| 工作日计划 | 工作日日历、例外日期、日期互算、修改历史、权限和阶段预警适配 | 6 人日 |
| 集成回归、上线与文档 | 角色权限、存量项目、跨年日期、异常场景、部署回滚和使用说明 | 3 人日 |
| **合计** |  | **20 人日** |

## 3. 功能规则

### 3.1 SI 信息扩展

- 在现有 SI 中新增 SI 类型、创作难度、参考书籍标题和参考书籍链接。
- SI 类型、创作难度采用字典或配置项；具体选项、排序和必填规则由甲方在开发前确认。
- 新字段贯通新建、编辑、详情、版本快照、预发布快照及整体回滚。
- 存量 SI 的新增字段默认留空，无需补填，不影响原有流程。

### 3.2 正文第 0 章

- 每个项目最多存在一个第 0 章，默认标题为“作品介绍”，固定排在其他正文章节之前。
- 第 0 章沿用现有章节的编辑、保存、提交、退回、批注、版本和定稿机制。
- 第 0 章纳入章节目录、质检合稿、重新质检、清稿、内容接口和最终导出。
- 存量项目不自动创建第 0 章；没有第 0 章的项目仍可按原流程完成。

### 3.3 批注回复

- 仅项目作者可回复项目编辑创建的有效批注，同一批注支持多条一级纯文字回复。
- 回复独立存储，不直接改写稿件正文，也不触发稿件新版本。
- 回复不支持嵌套、编辑、删除、附件、富文本或 `@` 提及。
- 批注失效后停止新增回复，历史回复继续保留并标记原批注已失效。
- 本期不因批注回复新增消息通知或外部消息推送。

### 3.4 工作日计划

- 新增工作日日历和例外日期，以周末为默认非工作日，并支持维护法定节假日和调休工作日。
- 在现有阶段计划上增加或完善计划开始日、计划结束日、计划工作日数和修改历史。
- 编辑仅可调整本人负责且尚未完成的项目阶段计划；作者只读，已完成阶段和流程实际时间不可被覆盖。
- 修改开始日或结束日时重算工作日数；修改工作日数时按开始日向后计算结束日。
- 日期计算支持跨月、跨年、法定节假日和调休；每次修改记录修改人、时间、原因及前后值。
- 现有阶段预警按工作日日历适配，不改变原有阶段解锁和完成规则。

## 5. 验收标准

- SI 新字段可正确保存、展示、进入快照和版本回滚，存量 SI 不受影响。
- 同一项目不能重复创建第 0 章；第 0 章在排序、提交退回、质检、定稿、接口、清稿和导出中的结果一致。
- 作者能够按照权限回复有效批注；回复独立留存，批注失效后不可新增回复，且不触发稿件新版本。
- 工作日日历能够正确处理周末、节假日、调休和跨年日期；计划日期互算、权限、修改历史和阶段预警符合约定。
- 管理员、编辑、作者三类角色权限正确，存量项目主流程不因本次改造受到破坏。
- 数据库变更可按说明部署，系统构建和本期相关自动化测试通过。

## 6. 范围边界

本期明确不包含：

- 编辑器表格及 Office/WPS 表格粘贴；
- Google Docs 或其他第三方在线文档协作；
- 创作平台与翻译系统的自动流转，以及翻译系统 API 改造；
- 沟通记录、附件上传下载和对象存储接入；
- 新增消息通知、即时通讯推送、短信或邮件提醒；
- 本期四项功能以外的现有系统重构、界面改版、性能专项优化或历史数据清洗迁移；
- 服务器、域名、SSL 证书及第三方服务的采购与费用。

## 7. 实施前必须确认的信息

- SI 类型、创作难度的选项、排序和必填规则。
- 第 0 章的创建入口、默认标题是否允许修改及相关角色权限。
- 批注回复的展示顺序、最大文字长度及批注失效判定口径。

- 测试与生产环境、数据库变更流程、备份与回滚方式及必要部署权限。
- 可用于回归验证的脱敏 SI、章节、批注和跨年计划数据。
