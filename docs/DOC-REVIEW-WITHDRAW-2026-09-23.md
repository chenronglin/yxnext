# 开始审核与作者撤回

## 当前规则

梗概、细纲、正文章节、质检稿共用同一流程：

作者编辑 → 提交待审 → 编辑点击“开始审核” → 修改/批注 → 通过或退回。

- 编辑点击“开始审核”之前，作者可以随时撤回、修改并重新提交，不限制经过时间和撤回次数，不设置时限配置。
- 查看稿件、待办、通知和历史不会自动开始审核。编辑在未开始审核时只可预览，正文编辑、文内批注、通过和退回均由前后端共同禁止。
- 编辑点击“开始审核”成功后，本轮提交立即不可撤回，不以是否保存修改为判断依据。页面直接进入可审核状态，不额外弹确认框。
- 编辑退回后作者可以修改；再次提交创建新的编辑草稿，重新等待点击“开始审核”。作者撤回再提交也遵循相同规则。
- 仅进行中项目的作者本人可以撤回；开始审核由项目编辑执行，管理员保留原有的代审核权限。已通过、退回、归档、完成等状态不能用撤回或开始审核绕过既有规则。
- 撤回保留正文、批注及提交历史，另记作者撤回版本；取消本轮审核待办并通知编辑，不调整项目阶段或交稿期限。
- 开始审核只写审核开始时间和审计，不生成重复正文版本、不关闭审核待办，不计作审核通过或退回。
- 提交报表仍记录实际提交动作：撤回再提交会增加一次提交记录，未改为去重后的绩效口径。

## 并发与多窗口

`doc_current_drafts.review_started_at` 记录本轮是否开始审核，空值代表未开始。新一轮新建草稿，标记自然重置。

开始审核和撤回都在数据库事务中竞争同一条草稿，原子匹配草稿 ID、活动状态、锁版本和未开始标记。开始审核会递增锁版本；撤回会封存旧草稿。双方同时点击只有一方成功，另一方刷新后才能继续，不会出现“已经开始审核且作者成功撤回”的状态。

同轮开始审核请求可重试，已开始的草稿不会重复记录开始时间或审计；并发争抢失败返回冲突。不同轮次的旧草稿请求始终拒绝。

待开始审核页面每 5 秒查询轻量交接状态，隐藏标签页暂停。编辑其他窗口开始审核后，本页刷新权限与版本；作者撤回后，编辑旧页暂停操作并保留页面内容。页面轮询只改善提示，实际权限以写接口事务校验为准。
