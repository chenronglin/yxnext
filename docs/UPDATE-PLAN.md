## 0. 计划约束

1. 本期只实施 SI 信息扩展、正文第 0 章、批注回复、工作日计划，以及四项功能必需的数据库变更、权限校验、回归测试、部署和使用说明。
2. 继续沿用现有 Next.js、Prisma/MySQL、Tiptap、角色权限、稿件版本、质检和导出流程，不进行整体重构。
3. 存量 SI 和存量项目不强制补录或迁移；新增字段应允许空值，存量项目无第 0 章时仍可完成原流程。
4. 新功能不得新增消息通知、外部消息推送或新的第三方系统依赖。
5. 数据库唯一性、权限校验、业务写入和操作日志应在服务层及事务内统一处理，不只依赖前端限制。
6. 每个工作包完成后立即补充测试并执行质量门禁，不把全部测试集中到最后三天。
7. 2026 年 8 月 18 日会议纪要用于核对需求来源和既有业务口径；实施范围仍以技术附件 V2.0 为准。会议纪要与技术附件不一致时，不得直接扩大本期范围，应先形成书面确认或变更。

### 1.3 必须继续遵守的工程约定

- BigInt ID 的接口出参统一转字符串，入参在服务层校验后转换。
- 业务错误使用稳定错误码和现有统一错误响应，不向前端暴露 Prisma 原始错误。
- 唯一性依靠数据库唯一约束兜底；并发冲突转换为明确业务错误。
- 业务写入、关联变更和操作日志尽量位于同一事务。
- 用户可见文案同步维护中英文 i18n 键，不新增硬编码文案告警。
- Migration 使用独立目录和 SQL 文件，写明变更原因、存量兼容和回滚方式。

## 3. 目标设计

### 3.1 数据库变更

计划通过一批可回滚 Migration 完成以下增量结构，最终字段名以详细设计为准：

| 结构 | 主要内容 | 兼容策略 |
| --- | --- | --- |
| SI 内部关联记录 | 以类别区分“SI 类型”和“创作难度”，保存编辑手工输入的名称及内部稳定编码 | 不提供管理员预配置入口；内部记录仅用于关系复用和历史兼容 |
| `StoryIdea` | 增加 SI 类型、创作难度、参考书籍标题、参考书籍链接 | 新字段可空，存量记录无需回填 |
| `DocCommentReply` | 文档 ID、批注 ID、回复作者、纯文字内容、创建时间 | 与稿件版本分离，不修改现有 JSON |
| `WorkdayException` | 日期、是否工作日、名称/说明、维护人和更新时间 | 仅保存周末规则的例外日期 |
| `ProjectStagePlan` | 计划开始日、计划结束日；现有 `planDays` 统一解释为计划工作日数 | 存量字段先兼容读取，不批量覆盖实际时间 |
| `ProjectStagePlanChange` | 阶段计划、修改人、原因、修改前后值和时间 | 只记录本期上线后的调整 |

数据库约束：

- 同一 SI 内部类别下稳定编码唯一，并发输入相同内容时复用同一记录。
- 同一文档、批注和回复 ID 唯一；按文档、批注、创建时间建立查询索引。
- 工作日例外日期唯一。
- 阶段计划历史只追加，不覆盖旧记录。

### 3.2 SI 信息扩展

实施任务：

1. 扩展 Prisma 模型、Migration、共享类型和 Zod 校验。
2. 在 SI 新建和编辑表单中把 SI 类型、创作难度改为最长 100 字的手工输入项，不依赖管理员预配置。
3. 扩展 SI 新建、编辑、详情和版本页面；服务端按输入名称匹配或自动创建内部关联记录。
4. 修改 `makeSnapshot()` 及创建、更新、标题更新、预发布和回滚路径，快照同时保存内部编码与输入名称。
5. 旧快照缺少新字段时按空值解析，不产生异常。
6. 参考书籍链接只允许双方确认的安全协议，并限制长度。
7. 回归现有 SI 标签行为，保证用户输入标签后仍可留痕并在下次选择，不引入统一预设标签或强制迁移。

完成条件：

- 四个字段可保存和展示。
- 版本快照、预发布快照和回滚结果一致。
- 手工输入值无需管理员预配置，历史版本始终显示保存时的名称。
- 存量 SI 无新字段时可继续原流程。
- 现有标签的录入、留痕和再次选择行为不因新增字段发生变化。

### 3.3 正文第 0 章

本工作包仅把现有从第 1 章开始的章节序号扩展为支持第 0 章；第 0 章用于填写书籍整体介绍说明，方便向运营交接内容，不包含表格能力或其他正文功能改造。

实施任务：

1. 将章节创建、修改 Route 的章节号校验由正整数改为大于等于 0 的整数。
2. 在新增章节和修改章节弹窗增加“设为第 0 章”选项；选中后章节号自动设为 0、数字控件禁用并自动填写标题“作品介绍”，普通章节数字控件仍从 1 开始。
3. 修改项目服务中 `chapterNo <= 0` 校验，同时保留章节号唯一约束。
4. 明确第 0 章的唯一键、创建、删除和重排规则；普通章节重排不得把第 0 章移出首位。
5. 修复页面中 `chapter.chapterNo ? ... : ...` 等真值判断，统一使用显式空值判断。
6. 核对章节导航、开放内容接口、清稿、质检生成、重新质检和最终导出排序。
7. 为并发重复创建第 0 章提供稳定错误码，不返回数据库原始异常。

重点文件：

- `app/api/projects/[projectId]/chapters/route.ts`
- `app/api/projects/[projectId]/chapters/[docId]/route.ts`
- `server/modules/project/project.service.ts`
- `lib/chapter-order.ts`
- `components/project/project-detail.tsx`
- `components/doc/chapter-navigator.tsx`
- `server/modules/open/open-project.service.ts`
- `server/modules/open/open-content.service.ts`

完成条件：

- 同一项目只能创建一个第 0 章。
- 第 0 章固定显示在正文最前。
- 第 0 章完整通过保存、提交、退回、批注、版本、定稿、质检、清稿和导出链路。
- 无第 0 章的存量项目行为不变。

### 3.4 批注回复

实施任务：

1. 新增 `DocCommentReply` 模型、Migration、共享类型和输入校验。
2. 新建回复服务，复用现有文档可见性和项目角色校验：
   - 仅项目作者可新增；
   - 仅允许回复项目编辑创建且当前仍有效的批注；
   - 内容为非空纯文字并执行最大长度限制；
   - 查询按约定顺序返回历史回复。
3. 新增接口：
   - `GET /api/docs/[docId]/comments/[commentId]/replies`
   - `POST /api/docs/[docId]/comments/[commentId]/replies`
4. 扩展 `discussion-sidebar.tsx`，在批注项下展示回复列表和输入区；无权限或批注失效时只读。
5. 批注失效时保留历史回复并展示状态，不物理删除回复。
6. 回复写入不得更新 `contentJson`、`lockVersion` 或 `DocRevision`，不得新增通知或待办。
7. 新增回复创建操作日志及中英文文案。

完成条件：

- 作者、编辑、管理员的读取和写入权限符合约定。
- 有效批注可回复，失效批注不可新增回复。
- 刷新、切换文档或查看历史后回复仍存在。
- 回复不改变稿件内容哈希、版本号和自动保存状态。

### 3.5 工作日计划

实施任务：

1. 新增工作日纯函数：
   - `isWorkday(date, exceptions)`
   - `countWorkdays(start, end, exceptions)`
   - `addWorkdays(start, count, exceptions)`
   - `previousWorkday(date, exceptions)`
2. 纯函数不访问数据库，统一使用明确时区和日期格式；覆盖周末、节假日、调休、跨月和跨年。
3. 新增工作日例外日期的管理员维护接口和最小管理界面，支持按年份查询和批量保存。
4. 扩展项目阶段计划，按已确认角色矩阵实施：
   - 编辑仅可修改本人负责、活动项目的未完成阶段；
   - 作者只读；
   - 已完成阶段以及 `startedAt`、`completedAt` 等实际时间不可被计划修改覆盖；
   - 修改起止日时重算工作日数；
   - 修改工作日数时重算结束日；
   - 每次修改必须填写原因并保存前后值。
5. 将现有自然日算法统一切换到工作日函数，重点核对：
   - `server/modules/si/si.service.ts` 创建项目初始计划；
   - `server/modules/project/project.service.ts` 阶段解锁和截止日；
   - `server/modules/doc/doc.service.ts` 阶段推进；
   - `server/modules/admin/admin.service.ts` 管理端计划调整；
   - `server/shared/project-stage-timeline.ts` 到期和提前预警。
6. 阶段重叠按照双方确认口径返回提示，不改变原有阶段解锁和完成状态机。
7. 预警继续使用现有通知类型，只替换日期计算口径，不新增通知类型。

完成条件：

- 起止日和工作日数能够双向计算。
- 周末、节假日、调休和跨年结果正确。
- 管理员可修改全部可写项目，负责编辑可修改本人项目的未完成阶段，作者只读。
- 修改历史可追溯，实际时间不被覆盖。
- 定时预警与页面截止日期使用同一工作日口径。

## 7. 数据迁移与回滚

### 7.1 上线前

1. 备份生产数据库并记录备份完成时间。
2. 在与生产结构一致的测试库执行 Migration。
3. 使用存量 SI、无第 0 章项目、带批注稿件和跨年阶段计划执行兼容验证。
4. 确认工作日日历数据已录入目标年度。
5. 保存上线前构建产物和数据库版本。

### 7.2 Migration 原则

- 新字段默认可空，不为存量记录制造伪数据。
- 新表上线时为空，不批量生成回复或历史记录。
- 不修改现有稿件 JSON。
- 不覆盖 `startedAt`、`completedAt` 等实际流程时间。
- 索引和唯一约束先在测试数据上检查潜在冲突。

### 7.3 回滚

- 应用回滚优先恢复到上线前版本。
- 数据库回滚脚本只移除本期尚未被生产业务使用的新增结构；若已产生新数据，先导出备份再执行。
- 如仅工作日日历配置错误，优先修正配置并重算未完成阶段，不回滚已完成阶段的实际记录。
- 回滚过程和结果写入部署记录。

## 12. 风险与阻塞处理

| 风险 | 影响 | 处理方式 |
| --- | --- | --- |
| SI 手工输入内容超长或口径不一致 | 保存失败或历史展示不统一 | 前后端统一限制为 100 字，保存前去除首尾空白并把名称写入快照 |
| 第 0 章在隐藏路径仍按正整数处理 | 质检、开放接口或导出遗漏 | 使用 `rg` 全仓检索 `chapterNo` 并以端到端测试兜底 |
| 批注只存在 JSON，锚点可能随编辑失效 | 回复关联错误 | 创建回复时校验当前有效批注；历史回复独立保存 |
| 工作日算法分散 | 页面、服务和预警口径不一致 | 所有日期计算统一调用同一纯函数，不保留内联毫秒算法 |
| 节假日和调休数据不完整 | 截止日计算错误 | 甲方提供并确认年度数据；缺失年份禁止生成未经确认的结果 |
| 非负责编辑尝试修改项目计划 | 越权修改 | 页面仅向管理员和负责编辑开放入口，服务端再次校验项目归属；作者及非负责编辑只读 |
| 20 日内出现范围变更 | 压缩测试或造成延期 | 严格执行书面变更，重新评估人日和工期 |
| 生产结构与代码基线不一致 | Migration 或发布失败 | WP1 核对生产差异，先在同构测试库演练 |
